# Architecture view — design

**Primary question:** How are problems grouped and how do domains interact?

**Main artefacts:** Problem domains, dependency edges, inter-domain contracts.

**Panels (conceptual):**

1. **Domain map** — clusters; problems within or linked to domains.
2. **Dependency & contract** — inspect/edit when a domain or edge is selected.

**Create specification for domain** opens or continues an **unhandled** specification; user continues in [Specification view](../specification/).

Lifecycle position: after [Problem](../problem/), before [Specification](../specification/) approval and [Task](../task/) execution — [../shared/design.md](../shared/design.md).
