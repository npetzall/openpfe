# Problem

## Summary

For work that should be local, the team still has to spend most context (and tokens) figuring out **what** to touch; the "how" and the target behavior are comparatively cheap once the locus is known.

## Longer problem

Exploration, tracing, and narrowing candidates dominate the session before a concrete edit plan stabilizes. Token pressure shows up as repeated wide prompts and re-grounding—not as the final patch size. The fuzzy "where" problem burns budget before "what outcome" or "what change" solidifies.

## Open questions

- Is "where" hard because of missing maps, missing tests, or real coupling?
- Would better entrypoints (docs, indexes, boundaries) shrink the search, or is the code shape the blocker?
